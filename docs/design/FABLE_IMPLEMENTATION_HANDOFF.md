# 페이블 전달용 — RED Boss Combat v0.3 구현 지시

첨부된 `RED_BOSS_COMBAT_GDD_v0.3.md` 전체를 먼저 읽고, 현재 Godot 기반 RED 그래픽 프로토타입에 전투 시스템을 구현해 주세요. 지금 프로젝트를 새로 만드는 것이 아니라 **기존 플레이어/카메라/그래픽을 유지하면서 전투 모듈을 추가**하는 작업입니다.

## 절대 변경하면 안 되는 핵심 사양
- 보스에게 한 번이라도 피격되면 즉사: 일반 공격, 치명적 공격 모두 포함.
- 방향키 화면 기준 8방향 이동, Z 빠른 3타 공격, X 패링.
- 치명적 공격은 카메라 보스 중심 확대+슬로모션, 현실 시간 0.20초 내 **해당 패턴의 허용 방향키 또는 X**를 눌러야 회피/패링.
- 패턴별 허용 방향과 패링 가능 여부를 데이터로 구분.
- 게임 세계 슬로모션이 현실 시간 반응창을 늘려서는 안 됨.
- 외곽선 없는 저채도 로우폴리 3D→2D 셰이딩, 붉은 장발 주인공, 직교 쿼터뷰, 1920×1080 유지.

## 구현 순서
1. 기존 프로젝트 파일 및 상태 확인, 백업/버전관리. 기존 스크립트를 이유 없이 덮어쓰지 않는다.
2. Input Map(방향키/Z/X/R)와 플레이어/보스의 FSM 구축.
3. BossAttackPattern Resource 및 공격별 상태·판정 데이터 구축.
4. 일반 보스 패턴 N01 + 즉사 판정 구현.
5. F01(→ 방향만 회피 가능) 구현. 포커스 0.10초(현실), `Engine.time_scale=0.18`, 반응창 0.20초(현실), 복귀 구현.
6. F04(X 패링만 가능) 및 부정확한 입력 시 즉사 구현.
7. Z 3타 공격, 보스 HP/경직/그로기, R 즉시 리트라이 구현.
8. 나머지 패턴과 디버그 오버레이/테스트 자동화.

## 구현 정확도
- 입력시간은 `Time.get_ticks_usec()` 사용. `Engine.time_scale`의 영향을 받는 게임 시간 타이머만으로 판정하지 말 것.
- 카메라 Tween은 `set_ignore_time_scale(true)` 사용.
- 치명적 판단 시작 후 첫 신규 키다운만 결정 입력이며, 눌러져 있던 키 자동 인정 금지.
- 도착 가능하지 않은 안전 공간 방향은 보스 패턴으로 선택하지 말 것.
- 30/60/120 FPS 환경에서 199ms 허용, 201ms 실패, 잘못된 방향/X 실패를 테스트할 것.
- 프로토타입에서 미정의 무기, 스킬, 스토리, 신규 그래픽 스타일을 임의로 만들지 말 것.

## 1차 납품
- 실제 실행 가능한 Godot 프로젝트 파일
- `BossTestArena.tscn` 테스트 씬
- 패턴 N01 / F01 / F04
- Z 연계, 방향 회피, X 패링, 즉사/재시작
- 공격/허용 행동/남은 반응시간/결과를 표시하는 개발자 오버레이
- 검증한 것과 미검증 사항을 구분한 README, 인게임 스크린샷, 플레이 영상

컴파일 및 Godot 에디터에서 실제 동작 확인이 불가능한 경우에는 그 사실을 명시하고, 단순히 코드 생성만으로 완료되었다고 주장하지 마세요.
