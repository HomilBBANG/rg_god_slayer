# RED — 고속 액션 및 즉사 보스 전투 시스템 기획서 v0.3

- 목적: 개발 AI ‘페이블’에 전달해 구현 가능한 단일 기준 문서
- 기술 대상: 앞서 기획한 Godot 4.x / GDScript / Forward+ 그래픽 프로토타입
- 화면: PC 1920×1080 / 16:9 / 직교 쿼터뷰 / 60 FPS 목표
- 상태: **기획 사양(미구현, 플레이테스트 전 초기값)**
- 유의: ‘페이블’을 별도의 엔진 API로 가정하지 않는다. 이 문서는 개발 AI가 Godot 프로젝트에 적용하는 작업 명세다.

## 1. 전투 한 줄 정의

**빠른 일반 전투를 이어가다가 보스의 치명적 패턴이 발동하면, 카메라가 보스로 급격히 당겨지고 세계가 느려진다. 플레이어는 실제 시간 0.20초 안에 패턴이 허용한 화면 기준 방향키를 한 번 누르거나, 해당 패턴에서 패링이 허용될 때만 `X`를 눌러 생존한다.**

핵심 원칙:
1. 보스의 **모든** 명중 공격(일반/치명적)은 플레이어를 즉사시킨다. ‘치명적’ 분류는 피해량 증가가 아니라 **카메라/슬로모션/순간 대응 시스템을 발동시키는 패턴 분류**이다.
2. **패턴마다 허용 방어 행동이 다르다.** 안전 방향은 한 방향 또는 복수 방향일 수 있고, 패링 가능 여부는 패턴 데이터가 정한다.
3. 특정 보스 패턴을 처음 보더라도 동작과 명암으로 공격 의도를 읽을 수 있어야 한다. 성공은 운이 아니라 관찰·학습·판단의 보상이다.
4. 모션, 카메라, 판정은 모두 빠르고 명료하게. 플래시/화면 흔들림으로 시야를 가리지 않는다.
5. 이미 합의한 3D→2D풍 로우폴리/저채도 그래픽, 인게임 캐릭터 비율, 고정 카메라의 방향을 보존한다.

## 2. 기존 프로토타입의 계승 항목

- 주인공: 붉은 장발의 여성 한 명. 창백한 피부, 회청색 눈(원화 특징), 검은 셔츠/와이드 슬랙스/검은 신발, 작은 은색 역삼각형 목걸이. 옆머리와 잔머리는 정돈하고 머리카락은 뒤로 넘긴 생머리 실루엣.
- 인게임 렌더: 6등신과 긴 다리, 멀리서는 이목구비를 생략. 외곽선 없는 로우폴리 모델 + 조명 반응 셰이더, 낮은 채도와 간결한 배경.
- 이동: 방향키(↑↓←→), 화면 좌표 기준 8방향. 이동 속도 초기값 3.4 m/s.
- 공격: `Z`, 기본 근접 공격. 장비/무기/세계관을 임의로 추가하지 않는다.
- 신규 입력: `X` 패링, `R` 즉시 재도전(사망 화면 전용), `Esc` 일시정지(선택).

## 3. 조작 매핑 및 우선순위

| 입력 | 보통 상태 | 치명적 판단 창(0.20초) |
|---|---|---|
| 방향키 | 화면 기준 이동 | 첫 신규 눌림 한 번을 **회피 명령**으로 판정. 해당 패턴의 안전 방향일 때만 즉시 지정 위치로 회피 |
| Z | 기본 공격/연계 | 무시(공격 예약·피격 회피 방해 금지) |
| X | 허용된 일반 패턴의 패링 시도(선택 기능) | 패링 허용 패턴일 때만 패링 성공 |
| R | 없음 | 없음. 사망 후에만 재도전 |

- 치명적 판단 중 키보드 **새 키다운(pressed, non-echo)** 이벤트만 채택한다. 창 이전부터 누르고 있던 방향키는 자동 성공으로 인정하지 않는다.
- 동시 두 방향의 키다운 또는 판정창 내 여러 버튼 입력은 **최초 유효 시각의 단일 행동**으로 해석한다. 최초 입력이 패턴과 불일치하면 실패(재입력 기회 없음).
- 방향키에 한해 카메라 줌 중에도 조작 기준은 **최초 일반 카메라의 고정 화면 방향**이며, 카메라 회전은 절대 발생시키지 않는다.
- 치명적 판정이 시작되면 공격 중/공격 후딜/일반 이동을 즉시 인터럽트하여 순간 대응이 항상 우선권을 갖는다.

## 4. 일반 공격과 치명적 공격 비교

| 속성 | 일반 공격 `NORMAL` | 치명적 공격 `FATAL_CINEMATIC` |
|---|---|---|
| 명중 시 | 즉사 | 즉사 |
| 카메라 | 일반 쿼터뷰 유지 | 보스 중심 포커스, 직교 줌 인 |
| 세계 속도 | 1.0 | 0.18 배 |
| 방어 방법 | 보통 이동으로 타격 영역 이탈, 명시적으로 허용된 패링만 사용 | 해당 패턴에 정의된 **방향 선택 또는 패링**, 0.20초 판정 |
| 실패 | 명중 판정 시 사망 | 창 만료/잘못된 선택 시 공격이 적중하며 사망 |
| 성공 | 일반 전투 즉시 지속 | 공격 회피/패링 연출 → 카메라 복귀 → 반격 찬스 |

### 일반 공격의 기준
- 예고(Windup): 0.30~0.55초 **게임 시간**
- 유효 타격(Active): 0.08~0.14초 게임 시간
- 회복(Recovery): 0.25~0.45초 게임 시간
- 회피 무적 버튼은 따로 두지 않는다. 공격 부채꼴·돌진 경로에서 직접 움직여 벗어난다.
- 패링 가능 일반 공격은 `parryable=true`로 정의할 수 있으나 초기 프로토타입은 일반 이동 회피 중심.

### 치명적 공격의 단계
1. **예고 `FATAL_WINDUP`** — 0.35~0.55초 게임 시간. 보스 모션, 바닥 타격 예고, 특정 효과음으로 패턴 분간. 아직 자유롭게 이동 가능.
2. **포커스 `FATAL_FOCUS`** — 0.10초 **현실 시간**. 카메라 대상점을 보스 중심에 가깝게 이동하고 Orthographic Size 15 → 9.5로 확대. `Engine.time_scale = 0.18`. 아직 선택 판정 시작 전.
3. **판단 `FATAL_DECISION`** — 정확히 0.20초 **현실 시간**. 선택 창이 열린 순간 한 번의 짧은 오디오/시각 신호를 재생. 사용 가능한 방향 또는 패링을 입력.
4. **결과 `FATAL_RESOLVE`** — 성공이면 회피 이동/패링 모션을 강제 재생하고 타격 프레임만 무적. 실패면 보스의 공격이 명중해 즉사.
5. **복귀 `FATAL_RECOVER`** — 0.16~0.22초 현실 시간. 시뮬레이션 속도를 1.0으로, 카메라 Size를 15.0으로 복귀. 성공 시 보스 후딜 0.55~0.90초 게임 시간.

**시간 설계의 핵심:** 슬로모션이 걸려도 판단 0.20초는 늘어나지 않는다. `Engine.time_scale`을 반영한 Timer만으로 반응 시간을 재면 안 된다. 실제 시각/입력 타임스탬프를 사용한다. 포커스가 완료되어 시각 신호가 표시된 순간을 판단 창 시작 시각으로 기록한다. 예고와 포커스를 별도로 줘서 0.20초가 단순한 불시 반응 테스트가 되지 않도록 한다.

## 5. 독특한 회피 시스템: 「안전 공간 판독」

이 시스템은 구르기 버튼을 누르는 방식이 **아니라 공격 장면을 읽고 살아남을 화면상의 방향을 고르는 방식**이다.

- `↑` = 화면 위 / `↓` = 화면 아래 / `←` = 화면 왼쪽 / `→` = 화면 오른쪽.
- 성공하면 해당 방향으로 약 1.8m의 짧고 선명한 **시네마틱 회피 스텝**을 실행한다. 0.12초 게임 시간 기준 모션. 타격 순간에만 무적.
- 실제 지형은 3D이고 선택된 방향은 카메라 평면의 수평 벡터를 지면(XZ)으로 사영해 구한다.
- 보스 패턴은 안전 영역/위험 영역을 `Area3D` 또는 타격 폴리곤으로 가진다. 공격 시작 전 안전 방향으로 이동한 도착점에 충돌 장애물과 위험 타격 영역이 없는지 검사한다.
- 패턴 허용 방향과 **현재 위치에서 물리적으로 갈 수 있는 방향**이 일치해야 한다. 안전 방향이 벽/낭떠러지/장애물 때문에 막히면 그 패턴은 선택하지 않는다(재배치 또는 다른 패턴 선택).
- 잘못된 방향, 창 만료, 타격 영역 잔류는 모두 즉사. 단순히 바닥 방향 표시를 외워 누르는 것이 아니라 보스 선행 모션도 대응 방향과 일치하게 설계한다.
- 시네마틱 회피는 일반 이동 속도와 별도로 작동한다. 0.2초 안에 1.8m를 직접 달려야 하는 식으로 구현하지 않는다.

## 6. 패링 시스템

- 패링 키: `X`.
- `parryable=false` 공격에 X를 누르면 실패. 모든 공격을 패링할 수는 없다.
- 치명적 패턴의 패링은 0.20초 판단 창 안의 신규 X 눌림으로 판정한다. 일반 패턴의 패링을 구현한다면 타격 순간 전후 ±0.10초 **게임 시간** 같은 별도 정의 사용.
- 패링 성공 시: 충돌 중화, 명료한 금속성/충격성 짧은 효과음, 0.05초 현실 시간 수준의 짧은 임팩트 멈춤(선택), 보스 경직 0.60초 게임 시간. 화면을 가리는 광원 폭발 금지.
- 패링 누적치 3회를 채우면 보스 그로기 1.2초 게임 시간. 패링으로 곧바로 적 처치 금지.
- 패링 가능성은 보스 무기/팔 동작 끝의 **짧고 밝은 은색 반짝임**과 고유 타격음으로 알린다. 일반 회피 패턴에는 해당 반짝임을 절대 사용하지 않는다.

## 7. Z 공격: 빠른 3타 연계

- `Z` 1타: 전체 0.25초 / 유효 타격 0.09~0.15초 / 피해 1.
- `Z` 2타: 전체 0.27초 / 유효 타격 0.08~0.16초 / 피해 1.
- `Z` 3타: 전체 0.33초 / 유효 타격 0.12~0.21초 / 피해 2.
- 추가 Z 입력 버퍼: 0.10초 게임 시간(현재 타격 종료 전). 연계 가능 단계에서 예약 발동.
- 공격 중 이동 감속: 35%; 발 회전/방향 보정 허용, 급격한 위치 순간 이동 금지.
- **치명적 판단은 모든 공격 상태보다 우선하며 항상 즉시 캔슬 가능**. 반응하지 못해 죽었는데 캐릭터 후딜 때문인 상황 금지.
- 아직 근접 무기 형태를 확정하지 않았으므로 테스트 단계에서는 추상적인 타격 궤적 및 `Area3D`만 사용. 임의로 총·검·마법 설정 추가하지 않는다.

## 8. 첫 보스 공격 패턴 테이블

**주의: 모두 명중 시 즉사.** 패턴이 정한 방향은 테스트용 기본 안전 방향이며, 실제 배치에 따라 타격 영역과 도착 가능성 검증 필요.

| ID | 구분 | 시각적 예고 | 허용 방어 | 반격 찬스 |
|---|---|---|---|---|
| N01 | NORMAL | 수평 전방 베기, 발끝 방향 선명 | 공격 범위 밖으로 이동 | 0.30s |
| N02 | NORMAL | 전방 짧은 직선 돌진 | 옆으로 움직여 경로 이탈 | 0.35s |
| N03 | NORMAL | 바닥 원형 충격 표시 | 원 바깥으로 이동 | 0.40s |
| N04 | NORMAL | 보스 팔을 뒤로 당기는 2연타 | 타격 영역을 연속 회피 | 0.45s |
| F01 | FATAL_CINEMATIC | 화면 왼쪽 공간을 크게 쓸어버리는 베기 | `→`만 | 0.70s |
| F02 | FATAL_CINEMATIC | 화면 오른쪽을 찌르는 일직선 돌진 | `←`만 | 0.70s |
| F03 | FATAL_CINEMATIC | 아래쪽까지 덮는 횡단 베기 | `↑`만 | 0.70s |
| F04 | FATAL_CINEMATIC | 방어 가능한 정면 내려찍기, 은색 반짝임 | `X`만 | 0.85s |
| F05 | FATAL_CINEMATIC | 상부 궤적의 낙하 강타, 은색 반짝임 | `↓` 또는 `X` | 0.70s / 패링 0.85s |

- F01/F02/F03 같은 방향형 패턴은 프로토타입에서 화면 공간을 기준으로 명확히 연출한다. 회전하는 카메라를 따라 조작 방향이 바뀌면 안 된다.
- F04만으로 패링 튜토리얼을 만들고, F05를 통해 **패턴 하나에 둘 이상의 정답**이 가능함을 검증한다.
- 프로토타입 보스의 패턴 시퀀스(디버그 기본): `N01 → N02 → F01 → N03 → F04 → N04 → F02 → F05 → F03 → 반복`. 처음에는 랜덤 선택 금지, 패턴 1개를 수동 실행하는 테스트 메뉴 제공.

## 9. 보스와 승리/사망 규칙

- 시험용 보스 체력: 12. 플레이어의 Z 1/2타는 각 1, 3타는 2 피해.
- 보스 피격 후 소폭 경직만 부여. 모든 Z가 보스 행동을 중단하게 하면 위험/보상 구조가 깨짐.
- 보스가 일반 또는 치명적 공격으로 플레이어에게 명중하면 **HP와 무관하게 즉시 사망 상태**. 본 버전에서는 보호막/부활/세이브 로드 무적/데미지 감소 없음.
- 실패 시 0.35초 이내 사망 피드백과 재도전 메뉴 표시. `R`로 0.8초 이내 보스 전투 초기 상태 복귀(에셋 로드 시간 제외).
- 리트라이 시 보스/플레이어 위치, 카메라, 남은 콤보, 입력 버퍼, 일시적 무적, 타임스케일을 모두 초기화.
- 보스 HP 0 이하: 공격 중단, 승리 UI 출력, Time Scale 1.0으로 복귀.

## 10. 카메라와 VFX 규칙

### 기본 카메라
- Orthogonal / Keep Height / Size 15.0.
- 수평면을 기준으로 내려다보는 각 52°, 수평 회전 45°, 목표점까지 거리 25m(직교 화면 크기에는 영향 없음).
- 기존 1920×1080, 16:9 화면, 플레이어 캐릭터 표시 높이 약 70~90px 지향.

### 치명적 패턴 카메라
- 확대: `Size 15.0 → 9.5` (0.10초 현실 시간). 보스에 초점을 맞추지만 주인공은 절대 프레임 밖으로 사라져선 안 됨.
- 초점: 보스 65% / 주인공 35% 가중 중간점으로 목표점을 정하고 보스에 시각적 중심을 둔다. 플레이어 화면좌표를 10%~90% 영역 안에 유지하도록 초점 보정.
- 카메라 수평/수직 회전 금지. XZ 세계 방향과 방향키가 어긋나면 안 됨.
- 슬로모션: 초점 시작부터 `Engine.time_scale=0.18`, 판단 시계는 현실 시간으로 별도 계산.
- 조명/색감은 로우폴리 회화풍 유지. 필름 블러, 강한 번짐, 큰 화면 진동, 화려한 이펙트, 두꺼운 윤곽선 사용하지 않음.
- 복귀: 결과 연출 뒤 `Size 9.5 → 15.0` 및 속도 0.18 → 1.0을 0.16~0.22초 현실 시간으로 부드럽게 복원.

### 의도 전달
- 보스 동작의 무게 중심/팔/몸통 실루엣으로 공격 방향을 알린다.
- 바닥에 흐릿한 색면으로 위험 영역 강조. 선택창에서는 화면 가장자리의 얇은 방향 힌트(디버그에서는 활성화, 최종 플레이에서는 끄기 가능).
- 패링 패턴만 유일하게 은색 반짝임 + 짧은 소리.
- 기획상 실패는 ‘내가 잘못 판단했다’는 인상을 줘야 하며, 카메라 시야 가림·입력 누락으로 죽은 것처럼 느껴져선 안 됨.

## 11. 상태 기계(FSM)

### 전투 전체
`IDLE → APPROACH → COMBAT → VICTORY | DEAD → RETRY`

### 보스 패턴
`SELECT_PATTERN → WINDUP → [NORMAL_ACTIVE / FATAL_FOCUS → FATAL_DECISION → FATAL_RESOLVE] → RECOVERY → SELECT_PATTERN`

### 플레이어
`FREE_MOVE ↔ ATTACK_1/2/3`, `FREE_MOVE ↔ PARRY`, 모든 생존 상태에서 `FATAL_DECISION`으로 최우선 전이, 성공 시 `SCRIPTED_DODGE/PERFECT_PARRY`, 실패 시 `DEAD`.

- 동일 프레임에 피격/방어가 중복 발생하지 않도록 `pattern_instance_id`, `decision_resolved` 플래그로 1회만 확정한다.
- 애니메이션 신호가 소실되거나 프레임이 떨어져도 FSM이 종료 불가능 상태로 멈추지 않도록 타임아웃 제공.
- 사망/재시작/승리/씬 전환 때는 강제로 `Engine.time_scale=1.0`, 카메라 기본값 복귀.

```text
res://combat/

  BossController.gd
  BossAttackPattern.gd
  BossPatternLibrary.tres
  FatalReactionController.gd
  CombatInputRouter.gd
  BossHitResolver.gd
  AttackDebugOverlay.gd

res://camera/
  CombatCameraDirector.gd
res://player/
  PlayerCombatController.gd
  PlayerMovementController.gd
res://scenes/

```

모듈별 책임:
- `CombatDirector`: 전투 상태, 공격 선택, 전투 개시/종료, 재시작.
- `BossController`: 패턴 선행 모션, 활성 타격 범위, 경직/반격 상태.
- `BossAttackPattern`: 패턴별 안전 방향·패링 여부·예고 시간·카메라 매개변수.
- `FatalReactionController`: Focus→Decision→Resolve→Recover, **단일 결정 확정**.
- `CombatInputRouter`: `_input(event)`에서 신규 방향키/X/Z 이벤트 처리, 자동 키 반복 무시.
- `CombatCameraDirector`: 보스 확대/초점/기본 시점 복귀. 현실 시간 트윈.
- `BossHitResolver`: 일반 피격 판정과 즉사 상태 전환을 단일 권한으로 관리.
- `AttackDebugOverlay`: 패턴 ID, 안전 방향, 허용 패링, 남은 시간(ms), 입력/결과 표시.

### 반응 시간 판정 의사코드

```gdscript
# 완성 코드가 아닌 로직 기준 예시.
# 아래 메서드/상태는 별도 Controller 구현이 필요함.
const DECISION_US := 200_000
var decision_started_us: int = 0
var decision_resolved: bool = false

func open_decision(pattern):
    current_pattern = pattern
    decision_resolved = false
    decision_started_us = Time.get_ticks_usec()

func on_new_action(action: StringName):
    if decision_resolved or state != FATAL_DECISION:
        return
    var elapsed_us := Time.get_ticks_usec() - decision_started_us
    if elapsed_us < 0 or elapsed_us > DECISION_US:
        return
    decision_resolved = true
    if current_pattern.allowed_actions.has(str(action)):
        resolve_success(action)
    else:
        resolve_death("wrong_action")

func check_decision_timeout():
    if state == FATAL_DECISION and not decision_resolved:
        if Time.get_ticks_usec() - decision_started_us > DECISION_US:
            decision_resolved = true
            resolve_death("timeout")
```

- `Time.get_ticks_usec()`처럼 단조 증가하는 타임스탬프를 쓰면 시간 스케일과 무관하게 경과 시간을 측정할 수 있다.
- Godot `Engine.time_scale`은 Timer 및 delta 기반 시뮬레이션을 변경한다. 카메라 확대·복귀 Tween은 `.set_ignore_time_scale(true)` 사용. 신호/타임아웃도 현실 시간 기준 처리.
- `_input`에서 새 키다운을 캡처하고 `is_echo()`를 걸러 키 자동 반복에 의한 중복 판정 방지.
- 타격 충돌은 `Area3D`와 collision layer/mask 또는 명시된 공격 기하 자료로 처리하고, 안전 공간은 도착점 검사.
- 입력 오차 진단을 위해 성공/실패 시간 ms를 화면 로그 및 CSV로 기록할 수 있도록 한다.

## 14. 테스트/검수 조건 (반드시 실제 실행으로 확인)

| 테스트 | 기대 결과 |
|---|---|
| F01에서 → 신규 입력을 199ms에 누름 | 회피 성공, 즉사하지 않음 |
| F01에서 → 신규 입력을 201ms에 누름 | 실패/사망 |
| F01에서 ← 또는 X를 누름 | 실패/사망 |
| F04에서 X를 150ms에 누름 | 패링 성공, 보스 경직 |
| F04에서 방향키를 누름 | 실패/사망 |
| F05에서 ↓ 또는 X를 누름 | 둘 다 성공, 각기 다른 반응 연출 |
| F04에서 X를 판단창 전부터 누르고 있음 | 자동 성공하지 않음 |
| Z 3타 공격 도중 FATAL 진입 | Z 모션 취소, X/방향 방어 정상 입력 |
| 치명적 연출 중 FPS가 30으로 하락 | 입력 창 현실 시간 200ms 유지, 중복 판정 없음 |
| 반응 성공 뒤 재시작 | `time_scale=1.0`, 카메라 Size 15, 상태 전부 초기화 |
| 보스 일반 공격 명중 | 일반/치명 구별 없이 즉사 |
| 안전 방향 끝에 장애물이 있음 | 해당 방향 패턴이 선택되지 않거나 보스/플레이어 위치를 조정 |
| 포커스 줌 중 | 보스와 플레이어 모두 화면에 보이며 조작 기준 변동 없음 |

**측정 목표**
- 정상 프레임 60 FPS에서 200ms ≈ 12프레임. 입력 이벤트는 프레임 이벤트로 기록하고 판정은 실제 경과 시간으로 계산. 30/60/120 FPS 비교 측정 필요.
- 정확한 성공/실패는 **허용 행동 일치 + 시간 충족 + 패턴 유효성** 세 조건으로 정의.
- 패턴을 30회 반복했을 때 카메라가 원래대로 돌아오지 않거나 Time Scale이 복구되지 않는 버그 0건.
- 플레이어에게 1회라도 보스 타격이 적중한 경우 생존 버그 0건.
